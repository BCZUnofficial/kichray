# KichRay — g_skiptime / NumPad 7

**База:** `BCZUnofficial/kichray`, `master`, commit `a2b067a6aee494dc56a5deef6f672682d0f7e248` (18.10.2026).

## Что добавлено

- `g_skiptime 1`: непрерывная перемотка игрового времени.
- `g_skiptime 0`: выключить непрерывную перемотку.
- **Удерживание NumPad 7**: временная перемотка независимо от значения `g_skiptime`. При отпускании восстанавливается прежняя скорость (если включено `g_skiptime 1`, перемотка продолжится).
- Время ускоряется коэффициентом **1000** относительно реального, как в старом отладочном обработчике `DIK_MULTIPLY`. 1 реальная секунда ≈ 16 минут 40 секунд игрового времени.
- Ускоряются отдельно ALife-время **и** время окружения: **движение солнца по небу, освещение, погодный цикл, день и ночь** идут быстрее.
- Если сделать сохранение прямо во время перемотки, достигнутая игровая дата сохранится, но временный коэффициент **1000** не попадёт в сейв.
- При открытом главном меню, игровом диалоге или паузе ускорение временно приостанавливается; клавиша не срабатывает внутри консоли. На выгрузке уровня сохраняемые коэффициенты восстанавливаются.
- Изменение действует **только в одиночной игре**, не вмешивается в игровую физику, системную скорость кадров или многопользовательский сервер.

## Состав архива

- `g_skiptime.patch` — патч Git к трём файлам C++ исходников.
- `apply_g_skiptime.bat` — применение патча с предварительной проверкой.
- `INSTALL_RU.md` — инструкция.

Изменяются **4 файла**:

1. `xr_3da/xrGame/console_commands.cpp` — новая консольная переменная.
2. `xr_3da/xrGame/Level.cpp` — удержание NumPad 7, переключение/восстановление двух коэффициентов.
3. `xr_3da/xrGame/game_sv_single.cpp` — поддержка изменения коэффициента времени окружения в одиночной игре (раньше метод ничего не делал).
4. `xr_3da/xrGame/alife_time_manager.cpp` — сохранение нормального коэффициента в сейв, даже если в момент сохранения время перематывается.

## Применение

1. Сохраните/закоммитьте локальные изменения в исходниках.
2. Получите актуальную ветку `master` (для этого патча сверяйтесь с указанным commit). Разархивируйте содержимое, например в `D:\mods\g_skiptime\`.
3. **Вариант 1:** выполните из командной строки:

   ```bat
   D:\mods\g_skiptime\apply_g_skiptime.bat D:\projects\kichray
   ```

   Здесь `D:\projects\kichray` — корень репозитория с файлом `XR_3DA.sln`.

4. **Вариант 2:** в корне клонированного репозитория запустите:

   ```powershell
   git apply --check "D:\mods\g_skiptime\g_skiptime.patch"
   git apply "D:\mods\g_skiptime\g_skiptime.patch"
   ```

5. Проверьте: `git diff --check` и `git diff -- xr_3da/xrGame/`.

Если предварительная проверка не проходит, не применяйте патч силой — это может означать, что исходники изменились после указанного commit или уже отредактированы вручную.

## Что собрать

1. Visual Studio → `XR_3DA.sln` → конфигурация **Release / Win32**.
2. Собрать проект **xrGame** (обычная сборка проекта, не обязательно `Rebuild` всего решения). При необходимости Visual Studio сама пересоберёт зависимости.
3. Из каталога сборки (указан в свойствах проекта; в основных настройках `$(SolutionDir)..\bin\`) скопировать **`xrGame.dll`** в `bin` установленной игры с заменой после резервного копирования.
4. `XR_3DA.exe`, `xrCore.dll`, `xrRender_R1.dll`, `xrRender_R2.dll`, шейдеры и Lua-скрипты **для этой правки менять не требуется**, если игра уже запущена на бинарном комплекте из того же актуального master.

Если DLL собрана на несовместимой ревизии движка/настроек проекта, используйте согласованный набор из одной сборки.

## Проверка в игре

1. Сохраните игру **в отдельный слот**; загрузитесь в одиночной игре.
2. Откройте консоль: `g_skiptime 0`. Удерживайте **NumPad 7** 1–2 секунды и отпустите: часы и положение солнца должны ускоряться только при удержании.
3. `g_skiptime 1`: время должно двигаться ускоренно без клавиши.
4. `g_skiptime 0`: обычная скорость должна восстановиться. Повторите с игровым меню/паузой и при смене уровня.
5. Сверьте не только часы, но также движение солнца по небу, погодные переходы, смену дня и ночи и поведение заданий/спавна. Сделайте тестовый сейв при активном ускорении, выключите `g_skiptime`, загрузите сейв и проверьте обычный коэффициент.

**Важно:** 1000x может резко перескочить скриптовые таймеры, задания, выбросы и события модификации. Проверяйте на тестовом сохранении. Исправления пока не проверены компиляцией MSVC и запуском самой игры — выполнена только проверка структуры и применимости патча.
