# R4 E1 — ресурсы и графические контракты

Пересобрать **XR_3DA и xrRender_R4, Release Win32**. Устанавливать EXE и DLL
вместе: renderer ABI теперь `0x00040000`; старую DLL загрузчик отвергает.
HLSL встроен в EXE; отдельная установка gamedata не требуется. ИИ не изменён.

- DDS: восстанавливаемый кеш, pin на время кадра, LRU освобождение, повтор после
  отказа, существующие младшие mip при давлении бюджета, padded rows. Нет прежних
  отсечек файла 64 МиБ и разрешения 2048. По умолчанию бюджет DDS 384 МиБ;
  `-kich_r4_texture_mb=384` задаёт 32–768 МиБ. Это payload реестра, не VRAM.
- Runtime UI/видео: динамический upload BGRA, обновление через WRITE_DISCARD,
  сохранение last-good при временном отказе, новый ресурс только при resize.
- Состояния: depth function, RGB/separate alpha, write mask, stencil, независимые
  sampler address/filter/LOD. Comparison sampler теней остаётся отдельным.
- Wallmarks: один проход после геометрии, до освещения; только albedo RGB,
  scene D24S8 receiver bit 1. Теневые карты остаются D32.
- Модели: кешированные группы индексов для валидного TBN и локального fallback;
  исходные вершины/веса и GPU skinning сохранены. Отсутствующий bump# может
  использовать штатный SoC dummy; настоящий bump не подменяется checker.
- Glow: плавное затухание/появление, reset после паузы/телепорта, сохранён facing,
  допуск конца статического луча не более 5 см. Динамические окклюдеры не добавлены.

Добавлены проверки восстановления кеша, DDS/pitch, runtime upload (реальное тело
функции с recording API), отдельного wallmark route и mixed-TBN geometry/shadow.
Основные portable-наборы R4 проходят. Они не являются проверкой драйвера.
MSVC, HLSL-компиляция драйвером и визуальная приёмка здесь не выполнялись;
MinGW отсутствует. Отдельный старый `r4_device/run_tests.py` заблокирован отсутствием
ожидаемого пути файла в зафиксированной им исторической базе.

Проверить в игре: кровь/следы пуль на стенах и моделях; меню/PDA/видеофон после
загрузки; вспышки/дым; сталкер и мутант с bump при движении/LOD; glow за стеной;
контрольные интерьер и бак/солнце. Для снимков смотреть `DDS_RESIDENCY`,
`MODEL_BASIS_PARTITION`, `DYNAMIC_TEXTURE`, эффективные states/samplers и `GLOW`.
Окончательный визуальный паритет не объявляется по portable-тестам.
