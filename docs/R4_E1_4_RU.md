# E1.4 — зернистость, накладные материалы и отбор теней деталей

Пересобрать **XR_3DA и xrRender_R4, Release Win32**, с зависимостями решения.
Обновить вместе `XR_3DA.exe` и `xrRender_R4.dll`. Публичный ABI не изменён.

- Зернистость использует `fx\fx_noise2`, масштаб, частоту смены смещения и
  мультипликативное смешивание по R2/1.6. Текстура проходит общий preflight;
  при её отсутствии шум отключён, debug-текстура не подставляется.
- Статические материалы с точным VS `wmark` получают отдельный проход альбедо
  перед освещением и ограниченное смещение. Глубина и нормали принимающей
  поверхности сохраняются. Динамические следы пуль не смещаются повторно.
- Для дополнительных теневых видов деталей используется пространственный
  индекс. Границы обновляются каждый кадр; устойчивое разбиение переиспользуется.
  Первые два вида обходятся без построения индекса. Выбор и порядок экземпляров
  совпадают с линейным отбором, включая ветер и тени от объектов за камерой.

В обычном `log_stable` примерно раз в две секунды обычной игры появляется
`[R4 E1.4 status]`: `fps_current` по последнему интервалу Present,
`fps_recent` по интервалам после предыдущего отчёта, число солнечных каскадов,
локальных теневых источников, граней и разрешение карт. Это счётчики успешно
отправленных проходов, а не измерение количества затенённых пикселей.
Меню, снимки, диагностические режимы и паузы представления не входят в новые
интервалы FPS. Строка `[R4 E1.4 details]` показывает работу отбора и время CPU.
Проверка периода использует уже полученную временную метку; ожиданий GPU,
новых GPU queries и покадрового форматирования этих строк нет.

Проверки: переносимые тесты материалов, проходов, шума, деталей, ресурсов,
capture, UI, телеметрии и интервалов FPS; HLSL через glslang; x86 Windows
кросс-компиляция DLL/presenter и проверка ABI. Они не заменяют сборку MSVC
и проверку изображения/FPS на D3D11.

Игровая проверка: прежняя аномалия, плакаты/мусор при движении камеры,
следы пуль, открытый вид и помещение с лампами. Для сравнения плавности пройти
тот же маршрут после прогрева без `d_snapshot`. Остальное мерцание, не связанное
с материалами `wmark`, этим патчем не объявляется исправленным.
