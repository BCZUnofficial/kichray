# E1.8 — тени, свет и устойчивость подготовки кадра

Пересобрать **XR_3DA и xrRender_R4, Release | Win32**. Заменить EXE и DLL
вместе: модельный интерфейс обновлён до ABI `0x00040000`. Изменений xrGame нет.
Шейдеры встроены в EXE; новый generated header включён в коммит.

## Изменения

- Непрерывная пологая поверхность больше не отбрасывается из коррекции теней
  только из-за большого расстояния между соседними пикселями. Проверяется
  неплоскостность квадрата, а недостоверная плоскость использует один shadow
  comparison. Реконструкция глубины выполняется относительно камеры с той же
  матрицей, которая использовалась при растеризации.
- Индекс теневых экземпляров деталей опирается на устойчивые ячейки кеша.
  Переупаковка растений обновляет границы вместо полной перестройки дерева.
  Перекрывающиеся LOD-диапазоны модели используют общий индексный буфер
  разделения корректного и отсутствующего tangent basis.
- Spot-свет сохраняет авторскую текстуру и поворот проектора для мира,
  игрока и NPC. Проекция не зависит от выделения теневой карты. Отсутствующая
  текстура оставляет аналитический свет, без checker.
- HUD получает сглаженную ROS-освещённость владельца; bump/gloss занимают
  отдельные слоты, не конфликтующие с локальными тенями и проектором.
- Восстановлены параметры тумана из CurrentEnv и смешивание combine с полным
  небом по контракту R2. Forward-туман включается только для явно разрешённых
  мировых материалов; HUD/UI не получают атмосферный туман.

## Проверка в игре

Сохранить прежние настройки и `r__detail_radius 60`. Проверить в обычном
режиме и `r4_debug_view sun_shadow` террейн под пологим углом, тень у ног
модели, приближение и удаление камеры. Разрешение и размеры солнечных
каскадов сохранены: этот патч не увеличивает плотность теневых texel.

Проверить текстуру фонаря на стене, поворот фонаря NPC, смену освещения рук
при переходе из помещения на улицу и дальний вид с туманом. Для диагностической
записи выполнить `log_record 1`, поставить `log_mark terrain`, `log_mark torch`
и `log_mark open_view` в соответствующих точках, затем `log_record 0`.
Повторить короткий участок с выключенной записью для сравнения плавности.

Периодическая сводка дополнена параметрами проекции камеры, состоянием HUD
и проекторов, классами ресурсов и режимом индекса деталей. В FrameMove
записываются до четырёх самых долгих callback за интервал (порог 5 мс) и
восемь вложенных фаз. Это локализует найденные секундные задержки, но само
по себе их не устраняет. При выключенной записи новые update probes не
читают таймер, не вычисляют RTTI и не выделяют память. Включённая диагностика
имеет конечную стоимость; вложенные времена нельзя суммировать.

## Проверки перед публикацией

Пройдены portable C++ suites деталей, моделей, материалов, ресурсов,
провайдера, игровых адаптеров, записи и телеметрии; извлечённые production
shader-тесты плоскостей, теней, тумана и проекторов. HLSL прошёл компиляцию
glslang и проверку cbuffer 944 байта. Windows x86 cross-check собирает R4 DLL,
проверяет её exports/ABI, presenter и интеграционные участки EXE.

Историческое сравнение lifecycle из `r4_device/run_tests.py` здесь недоступно:
локальная история не содержит исходные файлы его базового коммита. Это не
засчитывается как пройденная проверка. Полная MSVC/FXC-сборка, игровая картинка
и реальный FPS требуют проверки на Windows. Новые tests не доказывают полного
визуального паритета с R2 или устранения всех статтеров.
