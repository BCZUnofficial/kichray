# G3b.1 — наблюдаемая телеметрия R2/R4, schema 3

Основа: G3b `fa86b9d45297074d727e5187531050416985b690`.
Требования: `KichRay_G3b_1_Telemetry_Technical_Map_RU(1).md` из чата анализа логов.
Патч добавляет диагностику. Выбор материалов, списки отрисовки, алгоритмы
освещения, анимация, skinning, UI-ввод и порядок графических проходов сохраняются.
Это не реализация normal mapping, parallax или исправление изображения.

## Как снять данные

| Команда | Результат |
|---|---|
| `d_snapshot 1` | Следующий полный графический кадр, в том числе с открытым PDA, инвентарём или меню и при паузе. |
| `d_snapshot_key 88` | Снимок по физической клавише F12 без открытия консоли. Обычное действие этой клавиши также выполняется. |
| `d_snapshot_key 0` | Отключить диагностическую горячую клавишу. |
| `d_snapshot_ui pda` | Группа кадров «игра → PDA → возврат в игру». |
| `d_snapshot_ui inventory` | Аналогичная группа для инвентаря. |
| `d_snapshot_ui menu` | Аналогичная группа для игрового меню. |
| `d_snapshot_ui cancel` | Прекратить наблюдение; записать причину и накопленные события. |
| `d_snapshot_profile 30` | 30 графических кадров со счётчиками и доступными GPU-замерами; без подробных DRAW и словарей. Допустимо 1–120. |

Для UI-сценария введите команду, закройте консоль и открывайте/закрывайте окно
обычным способом. Сборщик сам не нажимает клавиши, не закрывает консоль,
не снимает паузу, не меняет фокус, не загружает уровень и не отключает сессию.
Фазы определяются наблюдаемым состоянием окон, а не фактом нажатия ESC.
Если запрос сделан уже в нужном окне, снимок окна допустим, но
`baseline_missing=1`: исходный кадр игры не выдумывается.

Файлы `snapДД.ММ.ГГГГ.ЧЧ.ММ.СС[_суффикс].log` создаются в `$logs$`
эксклюзивно, без перезаписи существующих. У каждого снимка есть request/capture ID;
у UI-сценария — общий group ID и session ID. Между фазами сохраняется ограниченная
лента событий. Тайм-аут, смена уровня, сброс/потеря устройства, завершение и отмена
имеют явные причины. Отчёт о завершении без графического кадра отмечен
`EVENT_ONLY_TERMINATION` / `frame_capture=NOT_CAPTURED`.

## Что связывается в отчёте

- Источник: путь/тип/родитель UI-виджета, его прямоугольник, alpha/clip, atlas UV,
  счётчики глифов без текста пользователя, PDA-страница/карта/маркеры,
  логические ячейки/стопки инвентаря и selected section.
- Материал: CPP/Lua-источник, доступные/выбранные element/pass, причина fallback,
  объявленные семантические sampler slots, source/compiled shader identities,
  defines и ограниченные выдержки фактических include-файлов при компиляции R2.
- Геометрия: источник UV, исходная нормаль и наличие tangent basis, packing,
  world/normal matrix, ограниченные проверки значений, связь с моделью/виджетом.
- Backend: фактические shaders/resources/states/targets/layout, стадия прохода,
  выходные ресурсы, clear/producer и возраст там, где backend их отслеживает.
  Ресурс, привязанный к shader slot, сам по себе не доказывает выполнение ветки
  шейдера или вклад в пиксель.
- Модели: уникальные наблюдаемые skeleton/visual/mesh identities, hash содержимого
  палитры и source frame, число команд, логические/загруженные/выделенные байты,
  Map/upload и повторное использование по проходам. Команды не называются NPC.
- Детали: реальный source frame, валидность и возраст, generation, wind/wave,
  отдельные списки камеры и теневых frustum, точные целочисленные размеры.
- Декали: известные callsite origins, request/reject/create/retained/selected/
  batch submission, lifetime IDs, TTL/fade/bounds. История до точки наблюдения
  остаётся неизвестной; имя DDS не используется для угадывания «крови».
- Свет: lifetime source serial, роль и отдельные validity для level record/controller,
  registered/active/candidate/policy/selected/submitted. Шесть граней point light
  связаны с одним источником. Политики R2 и R4 записываются как фактически исполняемые;
  совпадающие параметры источников не означают дубликат.
- Окружение и postprocess: входные/применённые значения, фактические passes,
  runtime texture upload/reuse/revision. Содержимое динамических текстур не выгружается.
- Оставшиеся CPU-потоки учитываются по UI/particle/static wallmark/skeletal wallmark/
  sky/cloud/glow/legacy model/unknown, без заявления «весь legacy capture = 0».

Идентичности по указателю ограничены текущим процессом. Hash исходной геометрии
или палитры — идентификатор содержимого, не счётчик поколения анимации.
Отсутствующие/неподдерживаемые данные имеют `NOT_AVAILABLE`, `NOT_INSTRUMENTED`,
`NOT_SUPPORTED`, `NOT_MEASURED` или уточнённый статус вместо правдоподобного нуля.
Паспорт EXE/DLL содержит реально сгенерированные build/source/shader IDs;
при сборке архива без Git не подставляется предполагаемый commit.

## Полнота, лимиты и стоимость

`schema=3`, `comparable_schema=2`: прежние counters остаются. Раздел
`COMPLETENESS` отдельно сообщает полный ли кадр, цела ли сводка,
сохранена ли атрибуция агрегатов, хронологический trace, словари,
UI-transition и GPU timing. Переполнение trace не означает неудачный рендер.

Хронологический DRAW trace ограничен бюджетами проходов. Агрегаты считают все
наблюдаемые команды; переполнение маршрутов попадает в явный OTHER с потерей
детализации. Словари UI/DECALS/NORMAL_MAPPING/DISTORTION и защищённые route samples
имеют собственные лимиты. Потери/усечения/лимиты записаны рядом с данными.
R2 дополнительно снимает первые 128 фактических binding observations независимо
для UI, decals, models и остальных команд; поздний UI не вытесняется миром.
Все 16 PS и 4 VS texture slots проверяются в этих выборках.

Новый необязательный `KichR4_GetTelemetryAPI` имеет собственный ABI 1.
Основной renderer ABI и `RenderSnapshotDraw` не изменены. GPU timestamp queries
читаются с DONOTFLUSH, без ожидания результата на CPU. Готовые замеры дописываются
только в файл совпадающих capture/engine/render IDs; графика другого кадра
не дописывается. Недоступность, disjoint, timeout и отмена явны. Перечень
GPU stages находится в самом отчёте; это не независимое измерение каждого draw.

Counter profile ограничен 120 кадрами и не строит подробные trace/словари.
Времена форматирования/записи и callback telemetry отделены, где измерены.
Даже counter profile имеет диагностическую стоимость: по нему нельзя объявлять
FPS обычной игры или сравнивать производительность разных сцен.

## Преобразование в JSON

```powershell
python tools/analyze_render_snapshots.py logs/snap_a.log logs/snap_b.log logs/snap_c.log --output analysis.json
```

Обработчик сохраняет исходные статусы, проверяет observed = retained + dropped (+ omitted для намеренно исключённых
обновлений counter profile),
суммы агрегатов с потерями, целостность обязательных разделов и принадлежность
GPU completion исходному кадру. Повторяющиеся секции не теряются. Большие ID
сохраняются десятичными строками, счётчики вычисляются точными целыми Python.
При нарушении инварианта код возврата — 1.

В JSON есть семантические группы и группы UI-сценариев по session/group ID,
изменения состояния и числовых memory counters относительно первого переданного
файла. Первый переданный файл не объявляется baseline автоматически. Увеличение
registry/cache capacity не называется утечкой; отсутствующий ресурс в ограниченном
словаре не считается освобождённым. R2/R4 сравнивают по смыслу прохода/объекта/
материала, не по одинаковому номеру draw или GPU handle.

## Границы измерения и проверка на Windows

- Gbuffer/readback, вклад отдельных текстур в пиксель, pixel coverage, GPU residency
  и полная история ресурсов R2 не измеряются. P2-выгрузка промежуточных изображений
  в этот патч не входит.
- R2 texture/surface descriptors наблюдаются в выборке; без достоверного parent/
  subresource отношения одинаковые handles не объявляются ошибкой aliasing.
- R4 diffuse pipeline не получает normal mapping/parallax от появления телеметрии.
  Геометрическая нормаль, texture normal и окончательная нормаль Gbuffer разделены.
- Проверки C++ с тестовыми интерфейсами и сборка реальным x86 Windows SDK проверяют
  логику/контракты; они не заменяют MSVC Release Win32 и запуск игры с драйвером.

Перед анализом реального изображения перестройте решение целиком (EXE и связанные
DLL должны соответствовать друг другу). Для каждой контрольной точки снимите
игру, PDA, инвентарь и меню; повторите открытие/закрытие и проверьте сохранение
level/session, pause/input owner, HUD/cursor. Отдельно снимите свежие static/skeletal
wallmarks, материал с normal/bump declarations, distortion и сцену с большим числом
fallback draws. Сравнивайте одинаковую камеру/погоду/настройки/фазу анимации;
различия состояния отчёт фиксирует, но не исправляет.
