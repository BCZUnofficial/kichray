# KichRayDX11 — B4.3a v1: первый игровой мост

База: `feature/dx11-r4-bridge`, коммит
`195623a` — `DX11 Cordon Render Test` с проверенным B4.2.

## Что теперь происходит

Запускается обычная игра: меню, загрузка сохранения, игрок, коллизия,
скрипты и симуляция мира. После загрузки уровня и окончания precache R4
рисует статическую локацию **в существующем игровом окне**, используя
настоящую матрицу камеры движка. WASD, мышь, прыжок и приседание остаются
игровыми. Свободная камера из B4.2 в этом режиме не используется.

Это первый игровой шаг, **пока переходный режим R1/R2 + R4**. R1/R2 остаётся
загруженным и выполняет свой обычный рендер, сохраняя существующие сервисы
движка и готовый кадр для возврата. В игровой вид выводится отдельный кадр
DX11 с геометрией, DDS и alpha cutout из B4.2. GPU-ресурсы между API не
передаются; копирования картинки DX9 в DX11 и обратного чтения GPU нет.

**В кадре DX11 пока нет моделей NPC, монстров, динамических предметов,
оружия и рук, игрового HUD, detail-травы, эффектов, полноценных материалов,
света, теней и неба.** Персонажи и предметы продолжают существовать в игре
и влиять на симуляцию. Для осмотра NPC и взаимодействия можно нажать F8
и вернуть обычный вид R1/R2. Это тест игровой камеры и жизненного цикла,
не готовая замена всего игрового рендера.

Полноценные материалы и освещение перенесены дальше. Следующие игровые
шаги — динамические и анимированные модели, оружие/руки, затем собственный
HUD/UI и дальнейшее отделение от DX9.

## Установка и сборка

1. Закрой игру. Сохрани проверенные `XR_3DA.exe`, `xrGame.dll` и
   `xrRender_R4.dll` от B4.2.
2. Скопируй **содержимое `FILES`** в корень `KichRayDX11` с заменой.
   Накладывай этот пакет поверх зафиксированного B4.2 (`195623a`).
3. В Visual Studio выбери согласованные **Release / Win32** либо Mixed / Win32.
4. Сначала пересобери **XR_3DA**, затем **xrGame**. Второй проект использует
   новую import library EXE, поэтому порядок здесь существенен.
5. Скопируй свежие **XR_3DA.exe и xrGame.dll вместе** в игровой `bin`.
   Переноси также обновлённые PDB, если обычно проверяешь сборку с ними.

`xrRender_R4.dll` от рабочего B4.2 подходит: её исходники и семь C-экспортов
в этом пакете не менялись. Можно пересобрать R4 заодно, но новый функционал
находится в EXE и небольшом подключении UI в xrGame.

Добавлены `KichR4Game.cpp`, `KichR4GameEngine.cpp`, `KichR4Game.h`,
`KichR4GameSession.h`. Обновлённый `.vcxproj` уже содержит их.
Для `KichR4Game.cpp` требуется **NotUsing PCH, /EHa (Async)**;
`KichR4GameEngine.cpp` использует обычный engine PCH. При сохранении своего
проектного файла перенеси эти настройки и новые ссылки вручную.

Добавлен один экспорт EXE `KichR4_GameSetModal(bool)` для согласованного
xrGame. Старые layouts/vtable `CRenderDevice`, `IRender_interface` и публичные
B0/B2/B3/B4.1/B4.2 C ABI не менялись. Новый xrGame требует соответствующий EXE.
Если новый EXE получает старый xrGame без UI-вызова, R4 ждёт handshake и
оставляет прежний вывод; в логе будет подсказка о пересборке xrGame.

## Запуск

Используй новый ключ:

```text
-kich_r4_game
```

Например, обычные параметры своего ярлыка дополни `-kich_r4_game`.
`-center_screen` можно добавить для привычного центрирования игрового окна.
Имя карты этому ключу не передаётся: оно берётся из загрузки реальной игры.
Сначала проверь своё сохранение на Кордоне.

Старый `-kich_r4_level l01_escape` лучше убрать из тестового ярлыка.
Если ключи оставлены вместе, игровой режим имеет приоритет: автономный
просмотрщик B3/B4.1/B4.2 не открывается. Без нового ключа прежние тесты
и обычный запуск R1/R2 сохраняют своё поведение.

На время этого процесса используется оконный режим с существующим стилем
окна движка. При разрешении рабочего стола он может выглядеть безрамочным.
Это позволяет чередовать DX9/DXGI Present в одном HWND. Сохранённый флаг
`rs_fullscreen` не изменяется; полный эксклюзивный режим для моста не включается.
Старое управление F11 из просмотрщика в игру не переносилось. Для смены
разрешения используй обычные настройки игры и `vid_restart`.

R4 использует прежнюю blt swap chain B3/B4.2 и Present с sync interval 1.
Этот пакет проверяет совместимость, а не производительность: старый кадр
R1/R2 ещё вычисляется вместе с новым, расход ресурсов выше, чем у будущего
самостоятельного R4.

## Переключение изображения

| Ситуация | Какой кадр выводится |
| --- | --- |
| Загруженный уровень, камера игрока, R4 включён | DX11, статический мир |
| F8 в игровом режиме | Переключение DX11 / привычный R1/R2 |
| Главное меню, консоль, загрузка, precache, пауза | Привычный R1/R2 |
| Инвентарь, PDA, диалог с активным получателем ввода UI | Привычный R1/R2 |
| Закрытие меню/диалога | Возврат к выбранному F8 виду |
| Ошибка R4 | R4 отключается до перезапуска игры, вывод продолжается через R1/R2 |

F8 срабатывает по нажатию; удержание не вызывает повторные переключения.
В меню и при потере активности клавиша не меняет режим. Если у тебя на F8
назначено собственное действие, для этого теста освободи клавишу.

В кадре R4 заголовок окна показывает `DX11 B4.3a | GAME CAMERA`.
При возврате к R1/R2 восстанавливается заголовок игры.
Открытие диалога меняет весь выводимый кадр: UI пока продолжает рисоваться
своим старым рендером. Прозрачного наложения DX9 HUD поверх DX11 здесь нет.

## Проверка на Windows

1. Запусти с `-kich_r4_game`. Должно открыться одно обычное игровое окно,
   затем привычное главное меню.
2. Загрузи сохранение на Кордоне. Дождись окончания precache. Должен появиться
   статический мир B4.2 с позиции игрока, а не вид свободной камеры сверху.
3. Пройди несколько метров, повернись мышью, присядь и подпрыгни.
   Проверь стены и коллизию земли: положение и движение должны соответствовать
   обычному игроку. Клавиши T/C/Z/Home из просмотрщика теперь ничего не
   переключают в R4 и остаются обычными игровыми назначениями.
4. Несколько раз нажми **F8**. Сравни положение камеры и крупных объектов
   между R1/R2 и DX11. Наличие рук/NPC/HUD в обычном виде и их отсутствие
   в кадре DX11 на этом шаге ожидается.
5. Открой и закрой инвентарь, PDA, главное меню, консоль. Проверь диалог с NPC
   через обычный вид. Окна должны оставаться видимыми, после закрытия возвращается
   выбранный режим. Если конкретное модовое окно не перехватывает ввод,
   используй F8 и сообщи, какое именно окно осталось скрыто.
6. Проверь Alt+Tab и возврат. Из консоли выполни `vid_restart`, затем снова
   пройди по уровню. DX11-сессия уничтожается до Reset DX9 и создаётся заново
   после precache. Выбор F8 сохраняется.
7. Перезагрузи сохранение. Если доступно, проверь переход на другую карту.
   Старая DX11-сцена должна освободиться; новая берётся из загружаемого уровня.
8. Выйди штатно. Повтори короткую проверку с другим старым рендером — R2/R1.
9. Запусти без `-kich_r4_game`: это проверяет привычный путь без моста.

Пришли полные логи R4 → R2 и R4 → R1, скриншот игрового вида DX11 и впечатления
от совпадения камеры при F8. Для снимка самого кадра DX11 используй средство
Windows: старый внутриигровой screenshot пока берёт свой DX9 render target.

## Что искать в логе

```text
[R4 bridge B4.3a] armed: game HWND + engine camera; ...
[R4 bridge B4.3a] level attached: l01_escape; waiting for playable camera / end of precache
[R4 bridge B4.2] loading: ...
[R4 bridge B4.2] ready: VBs=... DDS loaded=... fallback=...
[R4 bridge B4.3a] first GAME CAMERA DX11 frame presented: level=l01_escape HWND=... ...
[R4 bridge B4.3a] output=DX11 static world; same game HWND; ...
...
[R4 bridge B4.3a] end: reason=...; DX11_frames=...; ...
[R4 bridge B4.3a] cleanup=PASS: views=N/N flags=0x0 pipelines=N/N depth=N/N resources=N/N live=0 payload=0; HRESULT=0x00000000
[R4 bridge B4.3a] shutdown: ... DLL=released
```

Префикс B4.2 у загрузки ожидается: используются уже проверенные reader,
DDS uploader и level session. Новый B4.3a подключает их к игре.
`cleanup=PASS` подтверждает освобождение ресурсов, а не правильность всего
игрового изображения. Для принятия нужны камера, движение, переключение,
работающие UI/загрузка/Reset и визуальная проверка на Windows.

`DISABLED: step=...` содержит первый отказ R4. После него игра выводит обычный
кадр. Одна повторная попытка cleanup допускается; если устройство остаётся
живым, его owner и DLL удерживаются до безопасного освобождения/завершения
процесса. Ложный PASS в таком случае не выдаётся.

Числа `scene_generations` учитывают EXE-сессии, `cleanups` — успешное закрытие
созданных GPU-устройств. Сессия, оставшаяся на F8 legacy до первого DX11-кадра,
может не создавать устройство, поэтому эти два числа не обязаны совпадать.

## Изменения в коде

| Узел | Изменение |
| --- | --- |
| EngineAPI | Точный opt-in ключ, абсолютный путь R4 рядом с EXE, проверка старых API-таблиц, приоритет игрового режима |
| IGame_Level | Передача имени реально загруженной карты, остановка R4 до выгрузки уровня |
| CRenderDevice::End | Снимок окна/камеры/готовности до уменьшения последнего precache-кадра |
| DX9 adapter | После EndScene выбирается один путь Present; R4 закрывается до DX9 Reset/Destroy |
| HW | Временный оконный режим без изменения сохранённого rs_fullscreen |
| xrGame CUI | Сигнал о модальном UI, подтверждение согласованной версии EXE/xrGame |
| KichR4GameSession | Ленивая загрузка статического мира, внешняя камера, F8, resize и итоговая проверка владения |
| KichR4Game.cpp | Владение DLL/сессией, SEH-защита native вызовов, сохранение FPU, диагностика и возврат к старому выводу |

Меняется EXE-интеграция и небольшой вызов в xrGame. Реализации R1/R2,
их shader-проходы, water/SSAO и логика сохранений не переписываются.
Параллельной отрисовки DX9/DX11 в общий render target нет. Для выбранного
кадра используется отдельная swap chain соответствующего API.

Основание для временного blt Present в одном HWND: Microsoft описывает
чередование кадров разных graphics API как возможность blt-модели:
https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/for-best-performance--use-dxgi-flip-model
После завершения миграции эту переходную схему можно заменить самостоятельным
современным DX11 presentation path.

## Выполненные проверки

Новые наборы: 1123 проверки game session, 376 runtime/loader,
12 engine camera/gating + dedicated/editor guards, по 8 presenter/reset
проверок в Release и Debug. Отдельно сохранены проверки предыдущих этапов.

- Настоящая game session: внешний camera matrix, roll/асимметрия, tree world
  transform, отсутствие зависимости от свободной камеры, F8/удержание,
  модальный UI, resize, неверный HWND/viewport/NaN, отсутствующий уровень,
  22 позиции отказа native render API, в том числе неожиданные положительные
  результаты и освобождение частично созданных ресурсов.
- Настоящий EXE game runtime: точный ключ, путь DLL, ABI и исключения,
  UI handshake, ошибка кадра, переключение и Reset/перезагрузка,
  сохранение выбора F8, восстановление FPU, повторный cleanup и удержание
  DLL при живом устройстве.
- Из настоящей engine-функции проверены передача камеры/окна и запреты
  вывода при загрузке, precache, отсутствии view entity, меню, консоли,
  паузе, неактивности; dedicated/editor guards.
- Из настоящего DX9 adapter проверены порядок EndScene/выбор Present,
  отсутствие DX9 Present для R4-кадра, возврат к одному DX9 Present и
  освобождение R4 до Reset/Destroy — Release/Debug.
- Game session и runtime прошли ASan/UBSan. LeakSanitizer выключен из-за
  ограничений среды; владение проверяется явными счётчиками fixture.
- Старые B2/B3/B4.1/B4.2 и loader тесты прошли. 130 old/new DX9 lifecycle
  traces совпали в пяти конфигурациях обычного запуска.
- Win32 MinGW-w64: настоящие Game/Probe/ResourceProbe/FrameProbe EXE units
  скомпилированы и слинкованы; native R4 DLL пересобрана с настоящим
  D3D11 SDK; DX9 adapter проверен с реальным Win32/D3D9 SDK Release/Debug.
  Отдельная Win32 DLL успешно слинкована с новым UI-экспортом проверочного EXE.

Полная MSVC-сборка EXE/xrGame, вывод двух API в настоящее игровое окно и
прохождение сохранения на Windows здесь не выполнялись. Их проверяет
описанный выше игровой прогон. Числа фикстур не являются измерением FPS.

## Команды Visual Studio Developer PowerShell

Выполняй **в корне KichRayDX11 после успешной проверки**. Сначала переключение
и явная проверка тестовой ветки, затем добавление только файлов этого пакета.
Команды находятся ниже; `.ps1` для установки в архиве нет.

```powershell
$ErrorActionPreference = "Stop"
$testBranch = 'feature/dx11-r4-bridge'
git switch $testBranch
if ($LASTEXITCODE -ne 0) { throw "Не удалось переключить тестовую ветку" }
if ((git branch --show-current).Trim() -ne $testBranch) { throw "Открыта другая ветка" }
git merge-base --is-ancestor 195623a HEAD
if ($LASTEXITCODE -ne 0) { throw "Ветка не содержит базу B4.2" }
$packagePaths = @(
```
