# G3b: модели DX11, отдельные тени и проверяемая телеметрия

G3b продолжает G3a.1 на базе `085bcd0039dd35f58ea5e9548a08d1daa2dac9ec`.
Основание — аудит `KichRay_R2_R4_schema2_audit_20261022_1821(1).json`:
четыре пары R2/R4, подтверждённый неверный маршрут `static\fire_distort`,
потери подробных draw-записей и повтор камеры в теневых списках деталей.
В аудите нельзя доказать точный commit запущенных бинарников; новый код
проверяется отдельно от этих исходных снимков.
SHA-256 входного JSON: `cb01976ea7d08c205530930314f1bdbb148da5a1771722ba0b84c7b5d048eb82`.

## Изменение рендеринга

- Неизменяемые OGF-меши имеют постоянные DX11 VB/IB. Дубликаты визуалов
  разделяют исходный меш; экземпляр хранит transform, диапазон индексов,
  материал, выбранный элемент/проход и снимок костной палитры.
- В native R4 вершины моделей больше не разворачиваются и не скинятся на CPU
  каждый кадр. Палитра загружается один раз на команду кадра и используется
  повторно в геометрии, тенях и освещении. Частицы, UI и другие генерируемые
  потоки продолжают использовать stream path.
- Поддержаны rigid, 1W и 2W. Для software-режима 2W сохраняется исходный вес;
  hardware-режим сохраняет clamp и округление до u8. При одинаковых костях
  неиспользуемый вес не влияет на результат. Максимум — 256 костей.
  GPU-палитры ограничены 16 МиБ, кэш model VB/IB — 256 МиБ; превышение
  возвращает явную ошибку бюджета.
- Границы строятся по исходной геометрии и костям. Покадровая проверка
  трансформирует границы, а не все вершины. Неподтверждённые границы и raw-веса
  вне [0,1] не используются для отбрасывания объекта.
- Spatial-кандидаты собираются из камеры и выбранных теневых frustum.
  Повторный callback одного renderable исключается; команды проверяются
  заново для камеры, солнца и каждой локальной грани. Это консервативный
  отбор, не portal/occlusion visibility и не подсчёт видимых пикселей.
- Модели рук/оружия сохраняют собственную HUD-проекцию. Освещённый HUD
  рисуется перед постобработкой с отдельной очисткой depth; UI — после неё.
  HUD не попадает в теневые проходы.

## Материалы и огонь

`particles\xdistort` может иметь только специальный элемент E[4], без E[0].
Раньше `set_Element(NULL)` оставлял состояние предыдущего пламени. Теперь
обычный и специальный элементы выбираются явно; каждый их проход привязывает
свои shader/state/texture. Отсутствующий обычный элемент пропускается.

Искажение имеет отдельный `DISTORTION` pass: маска рисуется с depth test без
записи depth, затем отдельный fullscreen composite читает маску и готовую
сцену. Запись и чтение одного render target одновременно исключены.
Маска RGBA16F очищается в нейтральное (0.5,0.5); смещение равно
`(mask.rg - 0.5) * 0.05`. Прозрачные команды сортируются от дальних к ближним.
Меню сохраняет собственный эффект линзы. UV исходных частиц и sampler
материала сохраняются; глобального исправления через clamp нет.

## Детали и источники света

Детали используют независимый список теневых кандидатов из готового CPU-кэша
ячеек. Для каждого теневого прохода учитываются его frustum и расширение
границ на ветер. Камерный instance buffer не заменяется теневым. Область
покрытия явно обозначена `READY_CACHE_WITHIN_DETAIL_RADIUS`: это не обещание
теней деталей всего уровня. Legacy detail draws/vertices/indices остаются 0.

У локального света сохраняются процессный handle, serial времени жизни,
роль runtime/level, ordinal исходной level-записи и controller, когда они
известны. Совпадающие численные параметры не объединяют источники. Serial
сопоставим между кадрами одного запуска; между R2/R4-запусками он не является
общим ID. Ветка выбора теневых источников остаётся общей для сбора кандидатов
и GPU-планировщика.

## Телеметрия schema=2

`DRAW_AGGREGATE` считает все наблюдаемые callbacks независимо от подробного
trace budget: отправленные/пропущенные команды, треугольники и экземпляры.
Ключ содержит проход, свет, фазу, семантику, материал, фактический shader,
texture и state. Mesh/resource/UV остаются ограниченными примерами, а не
частью ключа, размножающей строки для каждого объекта.

512 основных маршрутов распределены между группами проходов; переполнение
попадает в явный `OTHER` своей группы и отмечает потерю атрибуции. Глобальные
счётчики остаются точными. Подробный лог по-прежнему может быть `INCOMPLETE`;
агрегат не восстанавливает потерянный порядок отдельных команд.

Общий draw budget остаётся 8 МиБ. Бывшие 512 КиБ forward разделены на
256 КиБ `FORWARD_TRANSPARENCY` и 256 КиБ `DISTORTION`.
`MODEL_RENDERER` показывает cache bytes, новые загрузки мешей, pose bytes,
число команд и реально отправленные draw calls. `MODEL_PASS` — кандидатов,
отсечения и отправки отдельной фазы. Нулевые CPU-expanded model bytes
относятся именно к native-моделям, а не ко всему capture-потоку.
Имена texture — метки источников со стороны EXE; реальные GPU handles
передаются провайдером. Для моделей и базовых поверхностей подстановка
заглушки явно помечается `CHECKER_FALLBACK:...`; это не GPU readback текстуры.
GPU model time пока `NOT_INSTRUMENTED`. Память реестра ресурсов не равна
физической резидентности VRAM; capture timing со snapshot overhead не
используется как доказательство прироста FPS.

## Адаптация X-Ray 1.6

Донор: `KaMeHb-UA/X-Ray-1.6`, commit
`e162d87600976f6fecb00b0a0861a8ae6ea5758a`.

| Источник/подход | Адаптация в текущую архитектуру |
| --- | --- |
| ModelPool / Instance_Duplicate | Общий неизменяемый mesh и отдельное состояние экземпляра |
| SkeletonX / 1B, 2B | GPU-палитра и раздельная семантика 1W/2W исходного SoC |
| R_DStreams | Повторное использование динамических буферов и WRITE_DISCARD для палитры |
| r__dsgraph / mapDistort | Явный специальный элемент, отдельная очередь и сортировка искажений |
| r4_R_render, r2_R_lights, r2_R_sun | Независимые camera/shadow subspace и отбор для конкретного света |
| particle_distort.ps / combine | Маска исходного RGBA и composite; нейтральная точка адаптирована к RGBA16F |

Полный SceneGraph, CoP engine и 3W/4W не переносились. Граница EXE/DLL остаётся
версионированным C API с собственными handle, без STL/D3D/engine pointers.
`KichR4RendererAPI` обновлён до ABI v3 и включает `KichR4ModelAPI`; EXE и R4 DLL
нужно пересобирать вместе. `RenderSnapshotDraw` не изменён. Старые R1/R2 и
CPU capture paths сохраняются и проверяются регрессионными тестами.

## Проверка и следующий запуск

Переносимые проверки компилируют production frontend, recorder и pass planner
с подменёнными границами GPU API. Проверяются кэш/диапазоны/палитры, 1W/2W,
переполнение, off-camera shadow candidates, material routing, отсутствие
RT/SRV alias, независимые detail buffers и ABI. Все 17 HLSL entry point
прошли glslang 14.0.0 с отражением Frame=816 и ModelPose=16400 байт.
MinGW-w64 GCC 13 выполнил компиляцию и компоновку x86 R4 DLL, проверку
экспортов и отсутствия импорта D3D9/D3DX9, компиляцию native presenter,
engine adapter без C++ exceptions, EXE/import client, C ABI и DX9 seams
в Release/Debug. Эти проверки не заменяют полную сборку MSVC, FXC и
запуск на Windows/D3D11.

На Windows пересобрать Release Win32 из одной версии исходников, включая
XR_3DA и xrRender_R4. Повторить четыре точки аудита и огонь с максимально
одинаковыми камерой, временем и погодой; снять `d_snapshot 1` в игре и меню.
Проверить:

1. `MODEL_RENDERER` — native GPU path, нулевые expanded model bytes,
   стабильный mesh cache и повторное использование pose в проходах.
2. Руки/оружие: проекция, анимация, освещение; rigid/1W/2W-модели:
   геометрия, нормали, диапазоны progressive mesh и тени.
3. `static\fire_distort`: специальный материал/texture, `DISTORTION/mask`,
   shader `PSParticleDistortionMask`; обычное пламя остаётся отдельным draw.
4. Объекты за камерой отбрасывают тени в видимую область; detail instance
   counts различаются между теневыми гранями, legacy detail счётчики равны 0.
5. Равенства агрегатов сохраняются при TRACE_LOSS. У совпадающих светов
   видны разные serial/role/record, если это разные источники.
6. Смена уровня, загрузка сохранения, меню, resize и возврат к R2/R1.

Оценка визуального соответствия и производительности требует этого запуска.
