# E1.7 — запись производительности и наблюдение за тенями

Пересобрать **XR_3DA и xrRender_R4 — Release Win32**, заменить EXE/DLL вместе.
Команды предназначены для нативного R4 (`-kich_r4_game`).

| Команда | Действие |
| --- | --- |
| `log_record 1` | Начать диагностическую запись в `log_stable.log` со следующего кадра. |
| `log_record 0` | Остановить дополнительный сбор и запись. Обычные ошибки движка остаются в логе. |
| `log_record` | Показать запрошенное и фактическое состояние. |
| `log_mark open_view` | Поставить временную метку; имя — 1–63 латинских символа, цифры или `_-.:`. |
| `log_watch 1` | Выбрать одну модель вдоль направления камеры и следить за её материалом, освещением и проходами. Требует включённой записи. |
| `log_watch 0` | Прекратить наблюдение за моделью. |
| `r4_debug_view normal` | Вернуть обычную картинку. |
| `r4_debug_view sun_shadow` | Показать результат солнечного PCF для непрозрачной геометрии. |
| `r4_debug_view hemi` | Показать коэффициент hemi. |
| `r4_debug_view baked_rgb` | Показать запечённый RGB. |
| `r4_debug_view sun_mask` | Показать исходную солнечную маску; в непрозрачном динамическом освещении она диагностическая. |

Запись по умолчанию **выключена** и не сохраняется в `user.ltx`.
`log_record 0` выключает дополнительные таймеры, отслеживание переходов и новые
замеры времени GPU. Рабочие правила HOM, отбора геометрии и разрешения теней продолжают
действовать. Явно запрошенный снэпшот имеет собственную диагностику.

## Короткий проверочный облёт

1. Загрузить то же сохранение и дождаться окончания загрузки. Установить
   `r__detail_radius 60` и `r4_debug_view normal`; не менять дальность травы между
   сравниваемыми проходами.
2. Выполнить `log_record 1`, закрыть консоль, затем начать `demo_record e17_flight`.
   Камера свободного полёта и управляемый объект учитываются отдельно.
3. Перед открытым видом поставить `log_mark open_view`, закрыть консоль,
   медленно повернуться, приблизиться и отдалиться. В проблемной точке поставить
   `log_mark shadow_flicker`; несколько секунд удерживать камеру неподвижно.
4. Для модели направить центр экрана на неё, выполнить `log_watch 1`, закрыть
   консоль и повторить изменение расстояния/угла. При `LOST` или `NO_CANDIDATE`
   выбрать объект заново командой `log_watch 1`.
5. Отдельно снять проблемную тень в `r4_debug_view sun_shadow`, а освещение модели
   — в `hemi` и `baked_rgb`. Затем вернуть `r4_debug_view normal`.
6. Завершить запись `log_record 0`. Повторить короткий участок с выключенной
   записью для сравнения плавности тем же внешним счётчиком кадров.

`demo_record` сам по себе не останавливает игровое время и не переносит игрока
вместе с камерой в Release. Для сравнения FPS оставить игру без паузы;
выход из свободной камеры — Esc. Неактивное окно, консоль, пауза, загрузка, диагностические виды,
снэпшоты и скриншоты исключаются из обычных измерений игрового кадра.

## Что можно установить по записи

Сводка примерно раз в две секунды разделяет обновление игры, подготовку рендера,
ресурсов и травы, теневые проходы и Present. Вложенные интервалы не следует
суммировать. GPU измеряется редко, с периодом не меньше 500 мс, без ожидания
результата; ответ относится к указанному исходному кадру, а не к текущему CPU-кадру.
История изменений ограничена; пропуски и переполнение отмечаются в записи.

`log_watch` выбирает пересечение луча камеры с уже рассчитанными границами
модели. Это **кандидат по bounds, не точное попадание в видимый пиксель**:
возможен объект за стеной. Значения hemi, исходной sun-маски, привязки текстур
и попадание центра bounds в каскады описывают CPU-входы. Они не измеряют яркость
пикселя и фактический результат PCF. Идентификаторы действуют в пределах
текущей сцены и регистрации; исчезнувшая цель не заменяется автоматически.
Результаты наблюдения выводятся вместе со сводкой примерно раз в две секунды;
во время меню или прерванного кадра наблюдение приостанавливается.

Состав отправленных объектов и размер солнечной карты также не доказывают
видимость тени. В этом патче нет постоянного чтения GPU-текстур, полного
копирования кадра или повторного рисования сцены ради наблюдения. Включённая
диагностика имеет конечную стоимость; сравнение `1/0` нужно для её проверки
на реальной игре. Полноценная MSVC-сборка и игровой FPS проверяются отдельно.
