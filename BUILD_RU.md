# Получение, сборка и установка

## Первый переход на объединённый master

Самый простой вариант — скачать [ZIP ветки master](https://github.com/BCZUnofficial/kichray/archive/refs/heads/master.zip) и распаковать в НОВУЮ папку. Не накладывайте его на старый `trunk` или установленную игру. Старые рабочие исходники и игровой `bin` сохраните для отката.

Для дальнейших обновлений удобнее новая копия Git: Visual Studio → «Клонировать репозиторий», адрес `https://github.com/BCZUnofficial/kichray.git`, новая пустая папка. Ветка `master`. Тогда обновления скачиваются через «Git → Получить» (Pull); отправка Push нужна только для ваших собственных изменений. Не копируйте `.git` из прежнего проекта.

## Сборка

1. Откройте `XR_3DA.sln` из корня новой копии. Используйте уже настроенные у вас Windows SDK, DirectX SDK и набор инструментов C++; не меняйте их только ради этого обновления.
2. Выберите **Release / Win32**, не Dedicated. В «Сборка → Диспетчер конфигураций» проверьте флажки сборки XR_3DA, xrCore, xrGame, xrRender_R1 и xrRender_R2.
3. Пересоберите решение. Если собираете проекты отдельно: сначала xrCore и зависимости, затем XR_3DA и xrGame; после них xrRender_R1 и xrRender_R2. Не переносите результат, если остались ошибки сборки.
4. Каталог результата указан в свойствах каждого проекта → Общие → Выходной каталог и в выводе сборки. В основных проектах он задан как `$(SolutionDir)..\bin\`, то есть `bin` рядом с папкой исходников, а не обязательно внутри неё.

## Установка в игру

1. Закройте игру. Сохраните резервные копии игрового `bin`, четырёх шейдеров ниже и важных сохранений.
2. Перенесите свежие `XR_3DA.exe`, `xrCore.dll`, `xrGame.dll`, `xrRender_R1.dll`, `xrRender_R2.dll` в игровой `bin` с заменой. Сохраняйте остальные необходимые библиотеки игры. EXE, xrCore и xrGame обновляйте вместе: пакет v8 добавляет метод xrCore, используемый xrGame.
3. Из `resources/shaders/r2/` перенесите в `gamedata/shaders/r2/` только `kich_particle_soft.vs`, `kich_particle_soft.ps`, `kich_bloom_build.ps`, `kich_graphics_math.h`. Другие шейдеры мода не заменяйте. Если gamedata отключена в fsgame.ltx, включите чтение `$game_data$`.
4. Новая игра не требуется. Загрузите сохранение, сделайте `save integration_test`, загрузите его. Проверьте повторную перезапись quicksave и переход на соседнюю локацию.

## Проверка графики

Используйте динамическое освещение R2. Сравнивайте один и тот же ракурс с одинаковыми настройками. Для исходного режима v9: `r2_soft_particles off`, `r2_bloom_mode 0`. Включайте эффекты по одному. Для сохранения выбранных настроек: `cfg_save`.

При черноте у частиц сначала отключите только `r2_soft_particles`. Если чернота осталась — отдельно установите `r2_bloom_mode 0`. Пришлите результат каждого переключения, актуальный `user.ltx`, журнал `bin/logs/log_stable.log` и скриншоты одного места. Наличие артефакта само по себе не доказывает его связь с мягкими частицами.

## Последующие обновления

В клонированной копии: сохраните свои правки коммитом, затем «Git → Получить» (Pull). При конфликте остановитесь и пришлите список файлов; не выбирайте массово «оставить всё моё/удалённое». После обновления пересоберите изменённые проекты и перенесите результаты по инструкции к обновлению.

При скачивании ZIP каждый раз распаковывайте в новую папку. ZIP не содержит истории Git и не обновляется через Pull.

Полная сборка Windows и проверка в игре выполняются пользователем. Изолированные тесты логики не заменяют MSVC/D3DX и визуальный тест.
