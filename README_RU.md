# Солнце, луна и объёмные лучи

[← Главная страница](README.md) · [Сборка движка](BUILD_RU.md)

Руководство для текущего `master`. Обновлено **18 октября 2026 года**.

**Рабочий вариант: Test E + 16 отсчётов в режиме 3 + исправление первого появления солнечного диска.** Изменения уже включены в исходники. Повторно запускать старые установщики `apply_experiment` и `apply_ex12` не нужно.

## Установка

1. Открыть [XR_3DA.sln](XR_3DA.sln), выбрать **Release / Win32**. Полная инструкция — в [BUILD_RU.md](BUILD_RU.md). Изменения солнечного диска находятся в `XR_3DA`, лучей — в `xrRender_R2`, согласование направления света — в общем коде рендеров.
2. Сохранить прежние игровые бинарные файлы и установить соответствующие результаты сборки. Шейдеры не заменяют необходимые изменения EXE и R2 DLL.
3. Скопировать из `resources/shaders/r2/` в игровую `gamedata/shaders/r2/` все четыре файла:

   - `accum_volumetric_sun.ps`;
   - `accum_volumetric_sun.s`;
   - `kich_sun_shafts_combine.ps`;
   - `kich_sun_shafts_combine.s`.

4. Для погоды проекта использовать согласованные конфиги из `resources/config/weathers/`. При переносе в другой мод сопоставить включения и имена секций: отдельный файл погоды может зависеть от описаний бликов в других файлах.
5. Запустить игру с динамическим освещением **R2** и включить эффект.

Шейдеры должны быть установлены до запуска нового рендера: его ресурсы создаются даже при выключенных лучах. Для обновления только с Test E до 16 отсчётов достаточно заменить `accum_volumetric_sun.ps`; пересборка для этого шага не нужна.

## Управление

| Команда | Действие | По умолчанию в коде |
| --- | --- | --- |
| `r2_sun_shafts 0` | Выключить эффект | `0` |
| `r2_sun_shafts 1` | 4 отсчёта на активный каскад | — |
| `r2_sun_shafts 2` | 8 отсчётов на активный каскад | — |
| `r2_sun_shafts 3` | 16 отсчётов на активный каскад | — |
| `r2_sun_shafts_intensity 0…2` | Интенсивность | `0.6` |
| `cfg_save` | Сохранить настройки | — |

```text
r2_sun on
r2_sun_shafts 3
r2_sun_shafts_intensity 0.6
cfg_save
```

Сохранённый `user.ltx` может переопределять значения по умолчанию. Дополнительные отсчёты уточняют выборку теней, а интенсивность усиливает весь эффект. Движок передаёт 4/8/12, актуальный шейдер преобразует последнее значение в 16. Старый комментарий о числе выборок в консольном коде не описывает текущее качество.

## Как устроен эффект

Это самостоятельная адаптация подхода [Clear Sky](https://github.com/v2v3v4/xray-csky/tree/main/engine/Layers/xrRenderPC_R2) к R2 / DirectX 9 «Тени Чернобыля».

1. При включённых лучах очищается позиционный буфер, чтобы небо не содержало геометрию предыдущего кадра.
2. Луч камеры берётся из позиции поверхности; для неба восстанавливается по проекции камеры.
3. Ближний и дальний солнечные каскады проверяют освещение вдоль своих участков пути. Учитываются поверхность, предел **180 м**, затухание и допустимые координаты карты теней.
4. Свет накапливается в отдельном `$user$kich_sun_shafts`: **половина ширины × половина высоты**, формат **A8R8G8B8**. Основной накопитель освещения для хранения лучей не используется.
5. Фильтр из девяти отсчётов сравнивает фактическую длину интегрирования. После достижения предела 180 м далёкая листва и небо совместимы; близкая поверхность продолжает отсекать неподходящий фон.
6. Результат аддитивно подмешивается после основного deferred combine, до forward-геометрии, облаков и оружия. Отметка текущего кадра защищает от использования старого содержимого буфера.

## Исправления

| Проблема | Изменение |
| --- | --- |
| Диск и направление теней расходились | Источник освещения согласован с направлением погоды |
| Лунный диск исчезал при нулевом направленном свете | Учтён `source_ignore_color` |
| Нежелательная засветка крон | Добавлены затухание, расчёт на небе и фильтрация по расстоянию |
| Регулярные полосы на лучах | Смещения выборок распределены по шагам; добавлено сглаживание |
| Тёмные точки на дальней листве через бинокль | Фильтр сравнивает ограниченную длину пути вместо разделения «небо / поверхность» |
| Лучи появлялись на заборе вплотную | Устранена классификация поверхности ближе 30 см как неба; уменьшен минимальный допуск фильтра |
| Солнце появлялось только после повторной загрузки | Начальная прозрачность диска задаётся при выборе дескриптора после сброса состояния |
| Недостаточная частота выборок в режиме 3 | Число отсчётов увеличено с 12 до 16 |

Владелец проекта подтвердил в игре устранение точек на листве, засветки близкого забора и описанного сбоя появления солнца. Режим 3 с 16 отсчётами успешно скомпилировался и работает. Это не заменяет проверки других сцен и оборудования.

## Погода и светила

Траектория задаётся ключами `sun_dir`. Это настроенный суточный цикл, а не астрономическая модель. Цвет направленного света задаёт `sun_color`; секция `flares` выбирает диск, гало и блики.

Ненулевой ночной `sun_color` может давать вклад в тот же эффект от направления луны. `source_ignore_color` управляет цветом диска и сам по себе не включает освещение. Отдельная погодная настройка `sun_shafts_intensity` не добавлена: интенсивность регулируется консолью.

## Ограничения и производительность

- Используется обычный путь динамического солнца, требуется `fp16_blend` и вызов объёмного прохода в ветке без `sunfilter`.
- Рассеяние приближённое; полноценная физическая атмосфера и HDR-буфер объёмного света не реализованы.
- Тонкие ветки могут теряться в карте теней, между выборками или при сглаживании. Пересечение ветки с диском на экране само по себе не гарантирует заметного луча.
- Переход с 12 на 16 увеличивает число выборок на треть, но это не означает падения общего FPS на треть. Сравнительных замеров времени кадра пока нет.
- Буфер сохраняет четверть числа пикселей полного кадра. Увеличение до полного разрешения не входит в текущий вариант.
- Сторонние шейдерные пакеты могут потребовать адаптации.

## Проверка и откат

Сравнивать режимы следует с одного ракурса при одинаковой погоде и интенсивности. Полезные сцены: деревья на фоне неба, листва через бинокль, забор вплотную, помещение, рассвет и ночь. Для проверки первого появления диска нужен полный выход из игры и загрузка сохранения после нового запуска EXE.

Если используется старый скомпилированный шейдер, при закрытой игре очистить только `shader_cache` в каталоге пользовательских данных. При ошибке сохранить лог и вернуть согласованный комплект прежних бинарных файлов и шейдеров.

Для диагностики полезны `log_stable`, текст ошибки HLSL при её наличии, параметры лучей, время/погода и два кадра с одинакового ракурса. Численные проверки не заменяют запуск MSVC/D3DX и игры на целевом ПК.
