# EX1.2 — God Rays для Kichray R2 (Clear Sky DX9; отдельный буфер)

**Статус:** эксперимент для проверки в игре. C++ и HLSL не компилировались в целевой Windows-среде; потребуется сборка `xrRender_R2` и игровой тест. Репозиторий на GitHub не менялся.

**Исходная база:** уже установленный EX1 (с работающими консольными командами `r2_sun_shafts` и `r2_sun_shafts_intensity`), затем один из шейдерных Hotfix03 / EX1.1 Test A. Если EX1 не установлен, этот установщик правильно остановится на этапе `-Check`. Не применять к чистому `master`: сначала EX1.

**Оригинал Clear Sky:** https://github.com/v2v3v4/xray-csky/tree/main/engine/Layers/xrRenderPC_R2 . Основная технология взята из `r2_rendertarget_accum_direct.cpp` и `r2_rendertarget_phase_combine.cpp`, но этот вариант является самостоятельной адаптацией под DX9 SoC.

## Архитектура

1. Создаётся дополнительный RT `$user$kich_sun_shafts`, формат A8R8G8B8, размеры `width/2 × height/2` (четверть пикселей полного кадра). Это не новый HDR-накопитель: старый `rt_Accumulator` больше не изменяется объёмным светом.
2. `accum_direct_volumetric()` работает во время активных солнечных каскадов NEAR и FAR с текущей картой теней. Каждый каскад пишет только в этот дополнительный RT, суммирование аддитивное. Затенение интерполируется вдоль луча камеры.
3. Перед отрисовкой forward-геометрии, облаков и оружия содержимое RT сглаживается и аддитивно подмешивается к `rt_Generic_0` после основного deferred combine.
4. Позиционный G-buffer очищается на каждом кадре при `r2_sun_shafts > 0`, чтобы небо определялось как пиксели без геометрии. Для них луч восстанавливается из матрицы проекции; это позволяет показывать лучи *на фоне неба*.
5. При отсутствии активного солнца, интенсивности 0 либо `r2_sun_shafts 0` лучи не рисуются; stale contents RT предыдущего кадра не используются.

Осталась зависимость от обычного пути динамического солнца, `RImplementation.o.fp16_blend` и ветки без `sunfilter` (унаследованная политика EX1). Это **ещё не** буквальный перенос полноценного HDR-объёмного пайплайна Clear Sky. Настройка `sun_shafts_intensity` из погодных `.ltx` не добавлялась. Экранное ослабление против солнечного направления — приближённая фазовая функция, не физически точная модель атмосферы. Просадки FPS и остаточные артефакты возможны.

## Установка (только PowerShell)

**Сначала** сохрани текущий вариант EX1 (рекомендуется также локальный git-коммит или отдельная ветка). Разархивируй EX1.2 в любую папку за пределами репозитория. Открой PowerShell в папке с `apply_ex12.ps1` и запусти:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\apply_ex12.ps1" -Repo "F:\kichray" -Check
```

При `OK`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\apply_ex12.ps1" -Repo "F:\kichray"
```

Создаются резервные копии старых файлов в `F:\kichray\_experiment_backups\ex1_2_дата_время`. Применение EX1.2 повторно заблокировано. Сценарий сначала проверяет ВСЕ места изменения; при ошибке во время записи пытается откатить все затронутые файлы.

Собери **`xrRender_R2` / Release Win32** в Visual Studio и скопируй **новую** `xrRender_R2.dll` из каталога результатов сборки в `bin` игры, сохранив старую. `xrGame.dll` для этих изменений не нужен.

### Шейдеры игры

Когда исходники уже пропатчены, скопируй четыре файла из `resources/shaders/r2` архива в игровую `gamedata\shaders\r2`. Либо запусти помощник из той же распакованной папки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\install_game_shaders.ps1" -Game "D:\Games\S.T.A.L.K.E.R. Shadow of Chernobyl"
```

Он создаст резервные копии существовавших четырёх игровых шейдеров в `_ex1_2_shader_backups` в папке игры. Если в папке игры лежат другие кастомные варианты `common.h` или `shadow.h`, **не заменяй их**: EX1.2 использует существующие.

**Важно:** новые `.s` и `.ps` должны быть в игре **до запуска** с новой DLL: они создаются при инициализации рендера даже при выключенных лучах. При ошибке компиляции HLSL сначала восстанови старую DLL и старые шейдеры.

## Тестирование

В динамическом освещении R2 запусти одну сцену с видимым солнцем, например Кордон между деревьями. Выполни последовательно:

```text
r2_sun_shafts 0
r2_sun_shafts 1
r2_sun_shafts_intensity 1
r2_sun_shafts 2
r2_sun_shafts 3
r2_sun_shafts 0
```

Качество теперь задаёт **4 / 8 / 12 выборок для каждого солнечного каскада** в RT с четвертью числа пикселей. Интенсивность — прежняя, диапазон 0–2. При смене качества пересборка DLL не требуется. Сравни скриншоты при 0/1/2 и измеренный FPS при фиксированном ракурсе. Проверь движение камеры, деревья на фоне неба, игру в помещении, вечер, ночь с молниями, `r2_sun_stable on/off`.

Если при дневном солнце лучей нет или появляются тёмные пятна, пришли `log_stable`, два скриншота с одинакового ракурса и параметры (`r2_sun_shafts`, `r2_sun_shafts_intensity`, погода/время). Если игра не запускается — `log_crush` с текстом ошибки HLSL или C++ компиляции.

## Что меняется

C++: `r2_rendertarget.h`, `r2_rendertarget.cpp`, `r2_rendertarget_accum_direct.cpp`, `r2_rendertarget_phase_combine.cpp`, `r2_rendertarget_phase_scene.cpp`.

HLSL/Lua: `accum_volumetric_sun.ps`, `accum_volumetric_sun.s`, `kich_sun_shafts_combine.ps`, `kich_sun_shafts_combine.s`.

Консольные команды, `r2_sun_stable`, существующие шейдеры bloom и soft particles не редактируются. Версия остаётся отдельной от `master`.
